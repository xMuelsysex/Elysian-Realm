# Web Observatory Stage Spike Design

## Boundary

This spike is a frontend visualization upgrade for the existing map tab. It is not a new simulation engine and must not move agents, create conversations, infer memories, or change world state locally.

## Stack Decision

Use `Pixi.js` for the spike.

Rationale:

- `Pixi.js` matches the project need for a renderer over server-owned state, similar to AI Town's web stage shape.
- It avoids Phaser's game-loop conventions that can tempt frontend-owned simulation logic.
- It can coexist with React DOM panels, text fallbacks, forms, replay controls, and debug views.
- It keeps the current `React + TypeScript + Vite + Node/TypeScript` foundation intact.

Deferred alternatives:

- `Phaser 3` remains a candidate if tilemap/collision tooling becomes necessary.
- `Sigma.js + Graphology` remains a side-panel choice for relationship/memory graph views, not the primary stage.
- Unity should remain archived/discarded for the MVP unless a future task explicitly revives it.

## Runtime Shape

- Add a React component that owns a Pixi `Application` lifecycle through `useEffect` and a DOM container ref.
- Feed it the existing `RealmMapViewModel` generated by `createRealmMapViewModel`.
- Draw deterministic display objects for:
  - location nodes;
  - links between locations;
  - agent markers within locations;
  - selected agent/location highlights;
  - recent event pulses.
- Convert percentage map coordinates into canvas coordinates at render time.
- Re-render from props whenever the backend-derived view model or language changes.
- Destroy Pixi resources on unmount to avoid leaking canvases or event listeners.

## Accessibility and Fallback

Pixi canvas content is visual-only. The existing DOM occupancy summary remains the accessible fallback and continues to expose locations/agents as text. Existing selection callbacks stay wired to buttons or accessible DOM where applicable.

## Data Flow

```text
AdminStateResponse -> createTimelineItems -> createRealmMapViewModel -> Web stage renderer
                                                         -> existing selection callbacks
```

Rules:

- No component may parse raw event payloads for stage state.
- No component may maintain authoritative agent position or location state.
- Local stage state is limited to renderer dimensions and hover/selection display behavior.

## Compatibility

- The `map` tab keeps timeline, replay, agent detail, diagnostics, topology, and location board panels.
- The existing DOM map/fallback can be kept or partially replaced, but text summary must remain.
- The spike should build in Vite without requiring browser-only APIs during Node tests.

## Rollback

The spike can be reverted by removing the Pixi dependency, the Pixi stage component, and the `RealmMapPanel` integration while leaving existing dashboard projections intact.
