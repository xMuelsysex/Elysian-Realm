# Unity C# API Design: Observatory Stage Prototype

## Purpose

Define the C# script/API shape before generating Unity implementation files. This design supports a standalone Unity URP prototype that renders a `1024 × 1024` observatory center stage from a local display-only JSON fixture.

## Design Principles

- Unity is visual-only for the first pass.
- Scripts consume `Assets/QA/stage-snapshot.example.json`; they do not call the backend.
- Stage coordinates use the reference `1024 × 1024` coordinate system.
- Main scene structure is generated by scripts, with manual tuning limited to camera, lighting, materials, and optional prefabs.
- Generated scene elements should be easy to delete/regenerate from a known root transform.
- Editor screenshot capture is part of the first pass.

## Data DTOs

### `StageSnapshot`

Responsibility:

- Root DTO for JSON fixture loading.
- Mirrors the future React-derived display snapshot.

Fields:

```csharp
[Serializable]
public sealed class StageSnapshot
{
    public int stageSize = 1024;
    public StageLocation[] locations = Array.Empty<StageLocation>();
    public StageLink[] links = Array.Empty<StageLink>();
    public StageAgentMarker[] agents = Array.Empty<StageAgentMarker>();
    public StagePulse[] pulses = Array.Empty<StagePulse>();
}
```

Validation expectations:

- Missing arrays normalize to empty arrays.
- `stageSize <= 0` falls back to `1024` with a visible warning.

### `StageLocation`

Responsibility:

- Display-only island/location node.

Fields:

```csharp
[Serializable]
public sealed class StageLocation
{
    public string id = "";
    public string label = "";
    public float x;
    public float y;
    public string theme = "cyan";
    public string occupancyLabel = "";
    public string recentActivityLabel = "";
    public bool hub;
}
```

### `StageLink`

Responsibility:

- Display-only bridge between locations.

Fields:

```csharp
[Serializable]
public sealed class StageLink
{
    public string sourceId = "";
    public string targetId = "";
    public float activity;
}
```

### `StageAgentMarker`

Responsibility:

- Display-only beacon/agent marker anchored to a location.

Fields:

```csharp
[Serializable]
public sealed class StageAgentMarker
{
    public string id = "";
    public string label = "";
    public string locationId = "";
    public string status = "active";
    public string color = "cyan";
    public bool selected;
}
```

### `StagePulse`

Responsibility:

- Optional event pulse effect at a location.

Fields:

```csharp
[Serializable]
public sealed class StagePulse
{
    public string id = "";
    public string locationId = "";
    public string source = "system";
    public float strength = 1f;
}
```

## Loader

### `StageSnapshotLoader`

Responsibility:

- Load a local `TextAsset` JSON fixture.
- Deserialize with Unity `JsonUtility` for minimal dependency.
- Normalize missing arrays.
- Expose clear warnings for invalid/missing fixture data.

Planned API:

```csharp
public sealed class StageSnapshotLoader : MonoBehaviour
{
    [SerializeField] private TextAsset snapshotJson;
    [SerializeField] private bool useFallbackWhenMissing = true;

    public StageSnapshot Load();
}
```

Rules:

- Fallback snapshot is allowed only for editor/debug resilience.
- The normal path should use `Assets/QA/stage-snapshot.example.json`.
- Warnings should make missing fixture obvious; no silent success.

## Coordinate Mapping

### `StageCoordinateMapper`

Responsibility:

- Convert `1024 × 1024` stage coordinates into Unity world positions.
- Keep coordinate conversion centralized.

Planned API:

```csharp
[Serializable]
public sealed class StageCoordinateMapper
{
    public int stageSize = 1024;
    public float worldWidth = 14f;
    public float worldDepth = 14f;
    public float yOffset = 0f;

    public Vector3 ToWorld(float x, float y, float elevation = 0f);
}
```

Mapping rule:

```text
stage x 0..1024 -> world x -worldWidth/2..worldWidth/2
stage y 0..1024 -> world z worldDepth/2..-worldDepth/2
```

## Rendering Orchestration

### `StageBootstrap`

Responsibility:

- Own the generated scene root.
- Load snapshot.
- Build island, bridge, beacon, waterfall, star dome, and pulse layers.
- Rebuild safely in editor/play mode.

Planned API:

```csharp
public sealed class StageBootstrap : MonoBehaviour
{
    [SerializeField] private StageSnapshotLoader loader;
    [SerializeField] private StageMaterialPalette palette;
    [SerializeField] private Transform generatedRoot;
    [SerializeField] private bool rebuildOnStart = true;
    [SerializeField] private bool clearExistingGeneratedChildren = true;

    public void Rebuild();
}
```

Build order:

1. Clear generated root.
2. Load/normalize snapshot.
3. Build star dome and ambient particles.
4. Build islands from `locations`.
5. Build bridges from `links` after location lookup.
6. Build waterfalls/energy streams around islands.
7. Build beacons from `agents`.
8. Build event pulse rings from `pulses`.
9. Frame camera.

Failure behavior:

- Missing link endpoint: log warning and skip that bridge.
- Missing marker location: log warning and skip that marker.
- Empty locations: log warning and build fallback five-location layout only if debug fallback is enabled.

## Materials

### `StageMaterialPalette`

Responsibility:

- Centralize theme colors and materials.
- Avoid hardcoding color values across controllers.

Planned API:

```csharp
[Serializable]
public sealed class StageThemeMaterial
{
    public string key = "cyan";
    public Color color = Color.cyan;
    public Material material;
}

public sealed class StageMaterialPalette : MonoBehaviour
{
    [SerializeField] private StageThemeMaterial[] themes;
    [SerializeField] private Material islandTopMaterial;
    [SerializeField] private Material islandRockMaterial;
    [SerializeField] private Material bridgeMaterial;
    [SerializeField] private Material waterfallMaterial;
    [SerializeField] private Material beaconMaterial;

    public Color GetColor(string key);
    public Material GetThemeMaterial(string key);
}
```

## Controllers

### `IslandController`

Responsibility:

- Generate a floating island from primitives or a lightweight prefab.
- Create top disc, rock base, foliage placeholders, hub dome if `location.hub`.

Planned API:

```csharp
public sealed class IslandController : MonoBehaviour
{
    public void Build(StageLocation location, StageCoordinateMapper mapper, StageMaterialPalette palette);
}
```

Primitive strategy:

- Use flattened cylinders/spheres for top surface.
- Use cone/cylinder/low-poly mesh primitive for rock underside.
- Use small cone/cylinder tree clusters.
- Use primitive dome/cylinder for hub building.

### `BridgeController`

Responsibility:

- Generate emissive curved bridge between two island anchors.

Planned API:

```csharp
public sealed class BridgeController : MonoBehaviour
{
    public void Build(Vector3 source, Vector3 target, StageLink link, StageMaterialPalette palette);
}
```

Implementation strategy:

- First pass can use `LineRenderer` with width and emission material.
- Optional later pass can replace with spline mesh.

### `BeaconController`

Responsibility:

- Generate vertical light beam, ring, icon/label placeholder above a location.

Planned API:

```csharp
public sealed class BeaconController : MonoBehaviour
{
    public void Build(StageAgentMarker marker, Vector3 anchor, StageMaterialPalette palette);
}
```

Implementation strategy:

- Ring: torus-like mesh if available, otherwise line/circle primitive.
- Beam: transparent/emissive cylinder or cone.
- Label/icon: optional TextMeshPro only if dependency exists; otherwise omit for first pass.

### `WaterfallController`

Responsibility:

- Generate energy/waterfall streams descending from island edges.

Planned API:

```csharp
public sealed class WaterfallController : MonoBehaviour
{
    public void Build(Vector3 islandCenter, float radius, StageMaterialPalette palette, int streamCount);
}
```

Implementation strategy:

- Use particle systems or simple line/ribbon renderers.
- Blue/cyan emission and alpha blending.

### `StarDomeController`

Responsibility:

- Generate or configure star dome/sky effect.

Planned API:

```csharp
public sealed class StarDomeController : MonoBehaviour
{
    public void Build(StageMaterialPalette palette);
}
```

Implementation strategy:

- Large inverted sphere or skybox-like background.
- Particle star field as child objects.
- Nebula gradient can be approximated with colored transparent planes/particles.

### `CameraRigController`

Responsibility:

- Configure square screenshot camera framing for the stage.

Planned API:

```csharp
public sealed class CameraRigController : MonoBehaviour
{
    [SerializeField] private Camera stageCamera;
    [SerializeField] private Vector3 position;
    [SerializeField] private Vector3 eulerAngles;
    [SerializeField] private float orthographicSize;

    public Camera StageCamera => stageCamera;
    public void FrameStage();
}
```

Recommendation:

- Start with orthographic camera for stable composition.
- Use perspective only if visual depth needs it and screenshot framing remains repeatable.

## Editor Capture

### `CaptureObservatoryStageScreenshot`

Responsibility:

- Provide repeatable `1024 × 1024` screenshot capture from Unity Editor.

Planned API:

```csharp
public static class CaptureObservatoryStageScreenshot
{
    [MenuItem("Elysian Realm/Capture Observatory Stage")]
    public static void Capture();
}
```

Behavior:

- Find `CameraRigController` or a camera tagged/named as the stage camera.
- Render to a `RenderTexture(1024, 1024, 24)`.
- Save PNG to `Assets/QA/screenshots/observatory-stage-prototype-YYYYMMDD-HHMMSS.png`.
- Refresh `AssetDatabase` after writing.
- Log the output path clearly.

Failure behavior:

- Missing camera: clear error log, no file written.
- Missing output directory: create it.
- Render failure: log error with enough context.

## Example Fixture

The first fixture should include five location nodes:

- `hub` at center, `hub: true`, gold theme.
- `northwest-grove` cyan/blue.
- `northeast-spire` violet.
- `southwest-garden` green.
- `southeast-harbor` cyan.

Links:

- Four radial bridges from `hub`.
- Optional top bridge between northwest/northeast islands.

Agents:

- One selected marker at `hub`.
- One marker on each surrounding island.

Pulses:

- 2-4 example pulses with `source` values like `agent`, `system`, `user`.
