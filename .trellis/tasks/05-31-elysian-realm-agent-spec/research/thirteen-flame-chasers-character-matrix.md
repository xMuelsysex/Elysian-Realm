# Thirteen Flame-Chasers Character Source Matrix

## Purpose

This matrix summarizes source anchors for future Elysian Realm persona configuration. It is a fan-research index and design aid only. Do not copy official dialogue, full story text, official images, audio, or extracted game assets into future persona files.

Use each row to seed structured persona facts, relationship constraints, memory prompts, and daily-life routines with explicit provenance labels such as `official-summary`, `wiki-summary`, `fan-analysis`, `project-authored`, or `generated`.

## Source Boundary

- Official HoYoverse/miHoYo pages are preferred as canonical URLs, but many are JavaScript-rendered and may need browser/manual verification later.
- Moegirl Wiki pages are accessible secondary summaries and useful for cross-checking roster, signets, relationship hooks, and story navigation.
- Bilibili story compilations and analysis videos are navigation/fan-analysis sources; use them to locate story beats, not as text to copy.
- GitHub Elysian Realm repositories found so far are mostly gameplay/strategy or asset-heavy data repos; use them for alias/keyword awareness only.

## Shared Relationship and Simulation Notes

- The Flame-Chasers should not be modeled as interchangeable chat agents. Each has directed relationships, unresolved grief, role obligations, and different comfort levels with daily-life scenes.
- The Elysian Realm setting is memory/data-oriented, so persona facts should be separated from generated memories and per-agent reflections.
- Slice-of-life behavior should remain character-consistent while creating original daily routines: archive work, workshop projects, music gatherings, market/shop encounters, quiet painting, training, counseling, observation, and unresolved memory fragments.
- Avoid giving any one character unlimited authority over the simulation. Powers such as Discipline, memory manipulation, engineering backdoors, or Elysia's social centrality should appear as constraints and tensions, not as shortcuts that bypass world rules.

## MVP Pilot Selection Notes

The existing project plan starts with 3 pilot agents and scales to 13 later. Strong pilot combinations:

1. **Elysia + Eden + Mobius**: strong contrast between social connector, artistic host, and boundary-testing scientist; good for conversation, memory, and relationship tests.
2. **Elysia + Pardofelis + Hua**: observation-terminal friendly; balances social scenes, ordinary-life errands, and restrained long-memory reflection.
3. **Griseo + Kosma + Aponia**: excellent for quiet perception, protective relationships, and ethical constraints, but more sensitive due to childlike persona boundaries.
4. **Vill-V + Mobius + Su**: good for LLM/tool boundary tests because engineering/science plans must remain typed events rather than direct state mutation.

Recommended first MVP trio for a living observation terminal: **Elysia, Pardofelis, Hua**. This gives one social catalyst, one ordinary-life/shop routine generator, and one restrained memory-burdened observer without immediately requiring complex multi-persona engineering or child-safety boundaries.
